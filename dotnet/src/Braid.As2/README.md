# AS2 outbound delivery

`As2Connector.SendAsync` accepts exact outbox bytes, their SHA-256, a globally unique delivery GUID, and an immutable partner binding version. Resolve `As2Partner` by that version in the delivery's tenant scope, including the signing key and the two partner certificate pins. Don't read the current route or regenerate the X12. Validate endpoint authorization, certificate lifetime/key policy and payload size at admission. The connector buffers one envelope in memory. Use `CreateTransportClient()` as a dedicated long-lived client with a bounded per-attempt cancellation deadline. Don't add redirect, buffering, authentication-challenge or retry handlers.

The supported profile is HTTPS, base64 `application/edi-x12`, detached SHA-256 CMS signature, AES-256-CBC CMS envelope, and a requested synchronous, signed SHA-256 MDN. The receipt must contain a DER detached RSA PKCS#1 signature by the exact pinned certificate, a two-part multipart/report, a processed disposition without warnings/errors, the original message ID, matching final recipient, and the MIC (digest of the signed MIME entity, including its headers). Partner and local AS2 IDs use unquoted ASCII tokens. This is a fixed profile, not automatic negotiation; qualify each binding against it.

The host adapter is `Braid.Triggers.As2.As2OutputDestination`. Register the AS2 route kind, its exact `TriggerConnectorReference`, destination binding GUID, the resolved `As2Partner`, a dedicated client, and `PostgresAs2ClaimFenceStore` using the restricted trigger-worker data source. Set the partner version using `As2OutputDestination.BindingVersion(connector, bindingId)`. The shared dispatcher passes the claimed row, not just its bytes.

The shared outbox has already committed `sending` before dispatch. Migration 0053 checks the tenant, target, live claim, binding, send number and output digest and writes the complete `As2Attempt` exactly once for that claim. The connector may POST only after that transaction commits. A crash leaves `sending` to expire to `unknown`; an uncertain fence commit does not permit a POST. Neither condition permits automatic resend. A later operator-authorized resend is a distinct outbox claim with its own fence record.

On `VerifiedTransportReceipt`, compare-and-set **only the same stored attempt** from unknown to transport delivered. `AlreadyFenced` changes nothing; `Unknown` leaves it held. For delayed evidence, use the untrusted message ID only to locate a candidate; call `As2Mdn.Verify` with that stored attempt, single-valued transport headers and bounded raw body. Apply the same idempotent state transition on success. Never substitute a new expectation, reuse a delivery GUID, or settle by MIC alone. Even a valid MDN is not a 997, 999 or other business acknowledgement.

For a separately supplied MDN in an isolated local recovery database, use `Braid.ReleaseTool.LocalAs2ReceiptRecovery.AcceptAsync`. Keep the database connections, administrator identity, full target, delivery ID and original fence claim ID under operator control. Supply only the receipt bytes (maximum 256 KiB) and its single-valued `AS2-From`, `AS2-To` and `Content-Type` headers from the received document. Never take the target, fence, key, database or actor from the receipt. Supply an already-open loopback evidence connection authorized to inspect the restored fence, and the existing release-writer connection string **on that same database**. The evidence query runs in a read-only transaction. Do not grant live workers table access or expose this operation as a network callback.

Only the first send is eligible: a resend reuses the Message-ID and MIC, so a later receipt cannot prove which attempt it acknowledges. On verification success the ordinary administrator resolution checks the target and send count again and journals the update; replaying identical evidence as the same actor is idempotent. A missing fence, mismatched scope, conflicting signed MIC or rebound claim is not permission to accept or resend.
