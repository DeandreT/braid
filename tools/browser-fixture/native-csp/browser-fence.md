# Browser-session fence transport (refusal-only)

Use the same trusted, launch-owned browser CDP session throughout. No external debugger or stock fallback. This protocol is **not** the packaged adapter. It establishes context-scoped browser document inventory, not closure of renderer or network producers. No response contains an accepting clean verdict.

1. Create a fresh isolated off-the-record context without pages. `Browser.beginBraidInventory({browserContextId,epoch,publicKey}) → {runId}`. Epoch is 16 random bytes in lowercase hex; publicKey is a raw Ed25519 key in lowercase hex. The generated run ID is bound to this browser session and context. Even a previously closed document makes late enrollment ineligible.
2. `Browser.readBraidInventory({runId}) → {revision,inventory,digest}`. Ordered, newline-separated `B|D:DocumentToken:frameTreeNodeId:rendererProcessId:parentFrameTreeNodeId` records are born/retired on the browser UI sequence at insertion/removal from Chromium's document-token map. `-` denotes no parent. Frame-tree node is not document generation. `digest` is lowercase SHA-256 of UTF-8 `runId:epoch:inventory`; revision is the event prefix length. No page URL or raw payload is returned. The ledger is bounded; overflow refuses.
3. For a pre-navigation fixture reservation only, `Audits.readBraidZero({epoch}) → {generation,producer}` acknowledges **one** original native load producer and its local CSP delegate. A credit is acquired before document construction and returned at `LoadEventFired` after native load dispatch. Missing original, pending load, outstanding/dropped/late CSP work, an observed violation, or an unsupported path refuses. This does not cover load-handler descendants.
4. Before closing the context, call `Browser.prepareBraidFence({runId,revision,inventory,digest,checkpoint}) → {snapshotToken,disposition}`. The browser compares exact records and revision, not counts. In the single-use fixture journal, checkpoint is `1:<journal HMAC digest>:<Ed25519 signature>`. The retained Node owner fsyncs the redacted combined inventory/producer commitment before signing UTF-8 `braid-fence-v1:<runId>:<epoch>:<revision>:<inventory digest>:1:<journal digest>`. No signing key goes to the page or renderer. A caller-provided digest alone is insufficient. A refused prepare may return a cleanup ticket; it is never a permission to claim success.
5. Close original pages/context, not the browser or private session. `Browser.verifyBraidDisposal({runId,revision,snapshotToken,digest,checkpoint}) → {disposed,disposition,inventoryRevision,transitions}`. Echo the frozen prepare revision, **not** the advanced disposal revision. `transitions` is the exact newline-separated suffix following prepare. A valid disposal-only suffix must retire precisely the frozen live tokens. Late births, invalid echo, premature verification or replay cannot produce clean. `disposed` is only a resource fact.

**Adapter gap:** the ticket is single-use and context-scoped, not yet a chain of page/replace/browser tickets. Parent frame-node IDs are not parent document tokens. No worker transfer or journal completeness can be inferred from document disposal. A renderer can return a load producer's zero receipt while an already-registered promise reaction can still publish a CSP-producing action. The `continuation` control demonstrates this with a real violation. Consequently do not normalize `renderer-producer-coverage-unproven` into a successful prepare or zero remaining work. Cleanup is independent and still required.

Use the paired offline fixture environment and run `unshare --user --map-current-user --net timeout 75 node "$FIXTURE/browser-fence-control.mjs"`. This control does not run the packaged catalog.
