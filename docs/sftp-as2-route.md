# SFTP intake and AS2 delivery on a mapping endpoint

The Host can scan a single read-only SFTP inbox for its target. Publish each file by rename to `order-id.sha256.ready`, using an ASCII order identifier and the lowercase SHA-256 of the exact bytes. Use a server-confined account and keep the directory below 4,096 entries. Nothing is renamed or deleted by the reader. A repeated listing of an admitted version reuses its durable work. A different digest is a different source version.

The restricted `braid_trigger_worker` login needs `CONNECT` before migration 0050. For an existing local installation, use `deploy/local/postgres-add-trigger-worker-role.sh` with a distinct worker password. Migration 0050–0053 installs trigger controls, the order/outbox transaction, scheduled discovery, operator resolution, and AS2 send fences. Do not grant the worker direct table access.

In Studio Operations, select the target, choose **Author local trigger route**, then **Configure SFTP to AS2 pilot**. Supply the registered source and partner binding IDs and versions, the granted machine identity, and the UTC schedule. Use generation `0` to create a disabled route; refresh **Triggers** and choose **Manage pilot route** to enable or pause the reviewed generation. A pause fences work from that generation. A stale request does not change the route. If the outcome is uncertain, recover the original operation instead of creating a new one. See [schedule and order outcomes](local-trigger-host.md#reading-schedule-and-order-outcomes) for catch-up, skipped runs and duplicate files.

The optional named JSON reference is an inline snapshot of up to 3,072 UTF-8 bytes. Its name must match the approved mapping's named JSON input. Studio stores its exact bytes with the route version. Admitted work rebuilds its request from that version, including the reference digest; editing a route cannot silently change previously admitted input. Do not put secrets in reference documents.

**Quarantined inputs and orders** lists rejection reasons and opaque record IDs, not source filenames or private documents. A too-large object, an invalid order, or bytes that disagree with the published digest do not prevent other files from proceeding. Correct the source and publish a new digest-named file. A failed mapped order cannot enqueue a delivery. Use delivery reconciliation, not a corrected input or a remap, when the failure concerns a remote send.

The endpoint starts its local worker only when both `BRAID_ENDPOINT_SFTP_ROUTE_FILE` and `BRAID_ENDPOINT_TRIGGER_WORKER_CONNECTION_STRING_FILE` are supplied. Both name private files subject to the endpoint's existing protected-file policy. The first is JSON using the following fields:

- `triggerId`, `source`, `sourceVersion`, `destination`, `destinationVersion`, `bindingId`: match the durable schedule and route; do not reuse a version for a different endpoint, key or certificate.
- `host`, `port`, `user`, `hostKey`, `inbox`, `sshKeyFile`: pinned SFTP server and read-only identity. The host key is the unpadded SHA-256 fingerprint without `SHA256:`.
- `tokenFile`: a protected, externally refreshed bearer token for the normal machine validator. The Host rereads it for each intake tick.
- `endpoint`, `sender`, `recipient`: HTTPS AS2 endpoint and AS2 IDs. The HTTPS chain must be trusted by the Host.
- `signingCertFile`, `signingKeyFile`, `encryptionCertFile`, `receiptCertFile`: protected PEM files. `signingSha256`, `encryptionSha256`, `receiptSha256` are the respective 64-digit certificate fingerprints. Rotate by enrolling a new binding version, never by editing an admitted version in place.
- `intervalSeconds`: 5–3,600. The schedule controls admission; dispatch of existing deliveries does not require another source object.

Mapping completion means the exact output and routed deliveries were recorded atomically. It does **not** mean the receiver accepted the message. A signed transport receipt is separate from a business acknowledgement. An interrupted AS2 send becomes unknown rather than automatically resending. Inspect deliveries in Studio Operations; an administrator must explicitly acknowledge duplicate risk before asking for another send of the retained bytes.

The local `SftpAs2RouteTests` gate uses an isolated PostgreSQL fixture and loopback SFTP/HTTPS servers. Supply `BRAID_SFTP_TEST_PYTHON` for a Python interpreter with Paramiko 4 and cryptography with DER CMS decryption support. The receiver decrypts the actual message, compares the X12 bytes, calculates the MIC and signs a receipt. The test uses a recording compiled-runtime fixture; it does not certify a mapping engine or a trading partner.

The two-target outage case drops the connection after the receiver takes the bytes but before it sends the MDN. Rollback changes the release for new work, not the status of that delivery. To reconcile it without resending, match the receiver's message ID and payload digest to the original send, then resolve **that delivery on that target** with its current send count. The operation records operator-reported acceptance, not a signed receipt. Without independent evidence, leave it unknown.

For the local recovery drill, the SFTP fixture supplies synthetic shipment-confirmation JSON. A managed test mapping produces X12 945 bytes; the independent receiver compares the decrypted payload against a separately specified expected document.

`NativeShipmentPackagePilot` exercises actual native Ferrule generation and sandboxed .NET execution. Opt in with `BRAID_NATIVE_SHIPMENT_PILOT=1`, the pinned service compiler/launcher and a disposable PostgreSQL fixture. Set `BRAID_SFTP_TEST_PYTHON` as well to run the complete loopback: scheduled SFTP intake dispatches the pinned DLL, the outbox retains its exact 945, and the AS2 receiver decrypts and compares it byte-for-byte. The outage case leaves one target's delivery unknown while another target delivers, then runs a fresh order through the rolled-back package before verifying the delayed receipt. Run from a stable, non-root, untraced process with no inheritable, permitted, effective or ambient capabilities. On Linux, if the parent has an inheritable capability, start the test with `setpriv --inh-caps=-all --ambient-caps=-all --no-new-privs --`; do not disable launcher origin checks. The single-transaction X12 schema declares fixed ISA12/GS08 version fields and integer quantity elements. Its expected wire image includes a newline after each segment terminator.

The test takes a full PostgreSQL custom-format logical backup **while the lost-MDN delivery is still unknown**. It provisions a separate fixture database with the same restricted grants, installs the source's exact migration sequence, compares the migration checksums, and loads the archive data and sequence values in one transaction. Recreating schema from logical DDL alone need not reproduce the exact catalog admitted by the Host. No worker connects during restore. Before resuming work, use fresh restricted connections to verify the exact output bytes, original release and request, retained response, delivery IDs, send counts and send evidence. An unknown delivery must not become eligible for automatic dispatch simply because it was restored. Cluster roles, partner secrets, and off-host disaster recovery are separate from this database drill.
